# 🚀 DISTRIBUTED RECOVERY POOL

Распределённая вычислительная платформа для восстановления собственных криптокошельков, ключей и других данных.

Есть старый кошелёк, утерянная часть данных или большое пространство вариантов, которое невозможно эффективно проверить на одном компьютере?
Distributed Recovery Pool позволяет объединить вычислительные ресурсы множества участников и распределить задачу между ними.
Каждый участник получает свой уникальный диапазон, поэтому одна и та же работа не выполняется несколько раз.

---

## 🎯 Зачем нужен проект?

- Некоторые задачи восстановления требуют проверки большого количества вариантов.
- Один компьютер может выполнять такую задачу очень долго. Распределённый подход позволяет разделить пространство поиска между несколькими независимыми участниками.

**Принцип простой:**

```
Большая задача
	  ↓
Разделение на диапазоны
	  ↓
┌─────────┬─────────┬─────────┬─────────┐
│ Worker 1│ Worker 2│ Worker 3│ Worker 4│
└─────────┴─────────┴─────────┴─────────┘
	  ↓
Параллельная обработка
	  ↓
Общий прогресс
```

Каждый участник работает со своим участком задачи.

## 🏠 Комнаты

Основная концепция проекта — Rooms.
Комната объединяет участников, работающих над одной категорией задачи.

Примеры:

- 🔐 восстановление криптокошельков с использованием различных ГСЧ;
- 🧩 восстановление известных частей мнемоник с использованием различных ГСЧ;
- 🔑 восстановление ключей при известных ограничениях с использованием различных ГСЧ;
- #️⃣ вычислительные задачи, связанные с хэшированием;
- ⚙️ пользовательские вычислительные задачи.

У каждой комнаты могут быть собственные:

- параметры задачи;
- диапазоны;
- правила распределения;
- настройки вычислений;
- ограничения;
- статистика.

- Создатель комнаты определяет её параметры и правила.

## 📦 Распределение задач

Одна из главных функций платформы — автоматическое распределение пространства вычислений.
Участнику назначается уникальный диапазон:

```
Room
 │
 ├── Worker #001 → Range A
 ├── Worker #002 → Range B
 ├── Worker #003 → Range C
 ├── Worker #004 → Range D
 └── Worker #005 → Range E
```

- Диапазоны не должны пересекаться.

Это позволяет:

- избежать повторной работы;
- максимально эффективно использовать вычислительные ресурсы;
- отслеживать вклад каждого участника;
- продолжать работу после перезапуска клиента.

## ⚡ Архитектура

Проект состоит из нескольких основных компонентов:

```
						Telegram Bot
						     │
						     ▼
					      ┌─────────────┐
					      │    Server   │
					      │             │
					      │ Rooms       │
					      │ Workers     │
					      │ Tasks       │
					      │ Statistics  │
					      └──────┬──────┘
						     │
					  ┌──────────┼──────────┐
					  ▼          ▼          ▼
					Worker 1   Worker 2   Worker 3
					  │          │          │
					  ▼          ▼          ▼
					Compute    Compute    Compute
```

- Сервер отвечает за управление задачами и распределение диапазонов.
- Worker отвечает непосредственно за вычисления.
- Telegram-бот предоставляет пользователю интерфейс управления и мониторинга.

---

## 💻 Worker

- После подключения Worker получает задачу от сервера.
- Далее он:
  - получает назначенный диапазон;
  - начинает вычисления;
  - периодически отправляет статистику;
  - сообщает о завершении диапазона;
  - получает следующий диапазон.

Таким образом, пользователю не требуется вручную распределять работу между компьютерами.

## 💰 ВОЗНАГРАЖДЕНИЕ

Участники получают вознаграждение за вычислительный вклад в выполнение задач комнаты.
Размер вознаграждения зависит от объёма диапазона, фактически обработанного Worker'ом на компьютере участника.
Чем больше диапазон обработан — тем больше вычислительный вклад участника.

### 📊 Как это работает?

После подключения к комнате Worker получает индивидуальный диапазон:

```
Room
 │
 ├── Worker #01 → Range A
 ├── Worker #02 → Range B
 ├── Worker #03 → Range C
 └── Worker #04 → Range D
```

После выполнения назначенного диапазона система фиксирует результат и рассчитывает вклад участника.
Например:

```
🖥 Worker #1842
Processed: 12 500 000 000 вариантов
Status: ✅ Completed
Contribution: 12 500 000 000
```

Вознаграждение рассчитывается на основании подтверждённого объёма выполненной работы в соответствии с правилами конкретной комнаты.
**🏆 Вклад каждого участника учитывается отдельно**

Участник может видеть:

- 📦 назначенный диапазон;
- ✅ обработанный диапазон;
- 📊 процент выполнения;
- ⚡ скорость Worker;
- 🏆 накопленный вычислительный вклад;
- 💰 доступное вознаграждение.

Таким образом, участник получает вознаграждение не просто за факт подключения к пулу, а за реальный объём вычислений, выполненный его компьютером.
**⚡ Подключай свой Worker → получай диапазон → выполняй вычисления → увеличивай свой вычислительный вклад.**

# 🔒 АВТОНОМНЫЙ РЕЖИМ

Выполняйте свои задачи без подключения к интернету
Участник пула не обязан постоянно держать компьютер подключённым к интернету.
Worker может работать полностью автономно.
Это позволяет использовать вычислительные мощности своего ПК, не передавая серверу исходные данные, параметры задачи или результаты вычислений в процессе работы.

### 📴 Работа без интернета
После получения необходимых параметров задачи участник может отключить компьютер от сети.
Дальше Worker работает локально:

```
┌───────────────────────────────┐
│         YOUR PC               │
│                               │
│  Worker                       │
│     ↓                         │
│  Local computation            │
│     ↓                         │
│  Range processing             │
│     ↓                         │
│  Local result file            │
│                               │
└───────────────┬───────────────┘
                │
          NO INTERNET
```

Все вычисления выполняются непосредственно на компьютере участника.

### 🔐 Конфиденциальность

Во время автономной работы Worker не отправляет результаты вычислений в пул.
Это позволяет участнику самостоятельно контролировать:
- исходные параметры задачи;
- вычисляемые диапазоны;
- результаты поиска;
- найденные значения;
- историю выполненной работы.
Никакие результаты не требуется передавать серверу автоматически.

##### 📄 ЛОКАЛЬНЫЙ ФАЙЛ РЕЗУЛЬТАТОВ

Worker автоматически сохраняет информацию о выполненной работе в текстовый файл.
Файл содержит зашифрованное представление:
- обработанного диапазона;
- состояния задачи;
- найденных результатов;
- необходимых служебных данных.

Пример:

```
Worker ID: 1842
Task: Recovery-01
Range: ENC: A7F2...91C4
Processed: ENC: 73D1...F082
Status: COMPLETED
Result: FOUND
Result ID: ENC: 91AF...72B1
```

Файл можно сохранить локально и использовать позже для синхронизации с пулом.

##### 🔎 КАК ПОНЯТЬ, ЧТО РЕЗУЛЬТАТ НАЙДЕН?

Worker отображает результат непосредственно в интерфейсе программы.
Например:

```
╔══════════════════════════════╗
║        TASK COMPLETED        ║
╠══════════════════════════════╣
║                              ║
║  Range:       COMPLETED      ║
║                              ║
║  Result:      ✓ FOUND        ║
║                              ║
║  Results:     1              ║
║                              ║
╚══════════════════════════════╝
```

Та же информация сохраняется в локальном текстовом файле.
Таким образом, участнику не требуется постоянное подключение к серверу, чтобы определить результат своей работы.

##### 📤 СИНХРОНИЗАЦИЯ ЧЕРЕЗ TELEGRAM

После завершения автономной работы участник может подключиться к интернету и передать сохранённый файл Telegram-боту.
Бот считывает информацию из файла и обновляет данные участника.
Например:

```
Worker #1842
Previous progress: 42.17%
Uploaded result: +12.4B processed
New progress: 54.61%
Status: ✓ Synchronized
```

##### 🔄 ОБНОВЛЕНИЕ ДИАПАЗОНОВ

Информация о выполненных диапазонах может обновляться двумя способами:

**📄 Через файл**

Участник отправляет Telegram-боту сохранённый текстовый файл.
Бот обрабатывает его и обновляет информацию о выполненной работе.

**💬 Через сообщение**

При необходимости участник может передать необходимые данные непосредственно сообщением через Telegram-бота.
После синхронизации пул получает информацию о диапазонах, которые уже были обработаны.
